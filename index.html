01 KNN 入门：什么是 K 近邻 入门基础层

1.1 生活化类比：物以类聚

你搬进新小区，想知道一家没去过的餐馆好不好吃。最自然的做法是：看看离你最近的几家常去餐馆评价如何——如果最近的几家都不错，你倾向于认为这家也不错。

再比如手里拿着一颗没见过的水果，根据大小、颜色、硬度找几个"最像的"已知水果：最像的三个里如果有三个都是橙子，那就判断它是橙子。

这些例子里藏着一个共同的假设：相似的输入，会产生相似的输出。这就是 KNN 唯一的、也是全部的核心假设（统计学习里称为"局部平滑假设"）。KNN 不去学习一个全局公式，而是在预测时现场询问最近的邻居。

于是 KNN 的所有问题最后都归结为两件事：
①怎么定义"相似"（距离度量，见 2.1）
②问几个邻居、怎么采信它们的意见（K 值与决策规则，见 2.3 / 2.4）。

1.2 核心思想：一句话定义

给定带标签训练集 D = {(x₁, y₁), …, (xₙ, yₙ)}，其中 xᵢ 是 d 维特征向量，yᵢ 是标签。对新样本 x：

  1. 在训练集中找出与 x 距离最近的 K 个样本，记为邻居集合 NK(x)；
  2. 用这 K 个邻居的标签决定输出：分类取多数投票，回归取（加权）平均。
分类（多数投票）与回归（均值）ŷ = argmaxc Σi∈NK(x) I(yi = c)　　　ŷ = (1/K) Σi∈NK(x) yi

其中 I(·) 是指示函数（条件成立取 1，否则取 0）。如果把公式读成中文，就是："在 K 个邻居里，哪个类别出现次数最多，就判给哪个类别。"

KNN 三要素（李航《统计学习方法》的标准表述，考试常考）：距离度量（谁算邻居）、K 值的选择（问几个邻居）、分类决策规则（怎么合并邻居的意见）。

1.3 惰性学习（Lazy Learning）：KNN 最重要的身份标签

先把这句话背准（本科考试与面试的高频点）：KNN 拥有训练数据集，只是不存在显式的训练（参数估计）过程。训练阶段只做一件事——把数据存起来；所有计算（算距离、排序、选邻居、投票）都被推迟到预测阶段执行。这就是"惰性"：把计算延迟到真正需要的时候。
说法判定为什么
KNN 不需要训练数据×它不需要训练过程，但预测时必须保留全部（或索引后的）训练数据。数据就是模型
KNN 训练快所以整体更省×训练 O(1)，但单次预测 O(nd)。省下的训练时间会在每一次预测时反复付出
KD-Tree 用来加速 KNN 训练×KD-Tree 是查询索引：增加训练期建树开销，降低预测期搜索开销（见 3.5.2）

惰性学习 vs 积极学习（Eager Learning）

对比维度惰性学习（KNN）积极学习（线性/逻辑回归、决策树、SVM、神经网络）
训练阶段只存储，O(1)（用 KD-Tree 索引时是例外）优化损失函数、估计参数，开销大
预测阶段与（至少一部分）训练样本逐一比较，慢一次前向计算或少量比较，快
"模型"是什么模型 = 训练集本身（非参数化，规模随数据增长）参数规模固定；训练完可丢弃数据（SVM 只留支持向量）
新数据到来直接加入即可，天然增量通常需要重新训练
可解释性局部解释："因为和这 5 个样本相似"全局解释：系数、规则
知识是否被压缩不压缩，占内存被压缩进参数或树结构

为什么计算机专业学生必须理解"惰性"？因为它决定了 KNN 的工程命运：复杂度在训练与推理两个阶段之间"搬家"，而线上服务最怕推理昂贵。KNN 适合离线批处理与中小规模在线服务，不适合大规模高 QPS 在线推理——这一条结论会一直用到第 4 章的技术选型。

02 KNN 核心原理拆解 原理深入层

2.1 距离度量：KNN 的"相似"到底怎么定义

KNN 里"相似"不是形容词，而是一个函数 d(x, z)。换一个距离函数，就等于换了一个"世界里的几何"，最近邻可能直接换人。设两个样本 x, z ∈ ℝd：

① 欧氏距离 Euclidean / L2 —— 闵可夫斯基 p=2 的特例d₂(x, z) = √( Σj=1d (xj − zj)² )
② 曼哈顿距离 Manhattan / 城市街区 / L1 —— p=1d₁(x, z) = Σj=1d |xj − zj|
③ 闵可夫斯基距离 Minkowski / Lp —— 统一形式dp(x, z) = ( Σj=1d |xj − zj|p )1/p,　p ≥ 1
④ 切比雪夫距离 Chebyshev / L∞ —— p → ∞ 的极限d∞(x, z) = maxj |xj − zj|
⑤ 余弦相似度与余弦距离 —— 文本 / embedding 检索主力cos(x, z) = (x · z) / (‖x‖₂ ‖z‖₂)　　dcos(x, z) = 1 − cos(x, z)

余弦只看方向、忽略长度：两篇都在讲"算法"的文档，一篇更啰嗦（词频整体更大），方向接近但长度不同，余弦仍判定高度相似。此外还有汉明距离（对应位置取值不同的维数，用于二值/类别编码）和马氏距离 dMa(x, z) = √((x−z)T Σ−1 (x−z))——它相当于"先去相关、再统一尺度，然后算欧氏距离"，代价是要估计并求逆协方差矩阵（O(d³) 量级）。

等距线的几何直觉（理解 L1/L2 差异的钥匙）

把"到原点距离等于 1"的所有点画出来：L2 的等距面是圆（各方向等价），L1 是菱形（沿轴走便宜、斜着走贵），L∞ 是正方形（只关心最大的一维偏差，其余维度"免费"）。直接后果有两个：

  • L2 会把单维大偏差平方放大，所以对离群维度敏感；L1 只按绝对差线性累加，更稳健（robust），实测中常表现为更抗噪的邻居选择。
  • L1 下的决策边界常出现沿轴折线（菱形角点的痕迹），L2 下的边界更平滑。

三个实战坑：
① 余弦距离 ≠ 免标准化：整体缩放不改变余弦，但逐维缩放会改变方向向量，通常仍需标准化或显式 L2 归一化。
② 度量与索引结构必须兼容：sklearn 中 metric='manhattan' 可用 kd_tree；而 metric='cosine' 不能配 algorithm='kd_tree'（KD-Tree 的划分与剪枝依赖欧氏几何），只能 brute 或 ball_tree，写错直接抛错。
③ 不要在未统一尺度的数据上比较"哪种距离更好"——那时你比较的是量纲，不是几何。

2.2 特征尺度：一个能毁掉整个模型的细节

构造一个必然发生的反例：特征 ① = 年收入（单位：元，取值 30000～300000），特征 ② = 年龄（取值 20～60）。样本甲（收入 50000，年龄 30）、样本乙（收入 52000，年龄 50）：

d = √( (52000 − 50000)² + (50 − 30)² ) = √(4,000,000 + 400) ≈ 2000.1

年龄的贡献是 √400 = 20，收入的贡献约 2000：年龄这一维对距离的影响被压到约 1%。如果业务问题恰恰是"找出年龄相仿的人"，模型会完全无视年龄，只按收入找邻居。

这不是"可能有点偏差"，而是数学上的必然：特征 j 对距离的贡献量级由其数值范围决定。范围大 10^k 倍的维度，贡献量级就大 10^k 倍。只要有一维量级压倒其余维度，欧氏距离就退化为单维距离，K 再怎么调也没用。

归一化 vs 标准化：必须严格区分的两个概念

min-max 归一化 NormalizationZ-score 标准化 Standardization
公式x' = (x − xmin) / (xmax − xmin)x' = (x − μ) / σ　（μ、σ 来自训练集）
结果范围映射到 [0, 1]，有界均值 0、标准差 1，无界
保留了啥保留原始分布形状保留"偏离均值多少个标准差"的相对位置
对离群值敏感：单个极端值拉大分母，把其余点挤到一小段区间相对稳健（极端离群仍会拉偏 μ、σ）
新数据超出训练集范围时映射后可能越界（<0 或 >1）不越界，只是得到较大的 |x'|
典型适用需要固定区间的场合：图像像素 /255、有明确物理边界、有界评分特征近似正态或长尾、量纲差异大；距离类算法（KNN）、SVM、PCA、线性模型的默认选择
主要缺点被离群值压扁后损失特征分辨率隐含假设"用均值和标准差概括分布"合理，极度偏斜时打折

怎么选（实用规则）：分布接近对称 → Z-score；取值有明确边界且需要固定区间 → min-max；有明显离群值 → 优先 Z-score，离群严重时用稳健缩放（中位数 + IQR）；不确定就都试，用交叉验证比结果，别凭直觉。

不该做标准化的场合：树模型（决策树/随机森林/GBDT 不基于距离，标准化无收益）；稀疏文本特征 + 余弦距离（Z-score 减均值会破坏稀疏性，内存可能爆炸，此时常用 L2 归一化）；已经是 0/1 的二值特征（min-max 后仍是 0/1，做了等于没做）。

工程铁律：防止数据泄漏（Data Leakage）

python正误对照
# 错误：在全量数据上 fit，验证集的均值/方差泄漏进了训练过程，CV 分数虚高、不可信
X_scaled = StandardScaler().fit_transform(X)
scores = cross_val_score(KNeighborsClassifier(), X_scaled, y, cv=5)

# 正确：缩放器写进 Pipeline，交叉验证时它只在每一折的“训练部分”上 fit
pipe = Pipeline([
    ("scaler", StandardScaler()),
    ("knn", KNeighborsClassifier(n_neighbors=5)),
])
scores = cross_val_score(pipe, X, y, cv=5)
为什么这条铁律这么重要？因为它是"作业分数虚高、上线立刻翻车"的头号原因。缩放参数是可学习的统计量（μ、σ、min、max），它们一旦看过验证集/测试集，评估结果就不再代表真实泛化能力。

2.3 K 值的选择：KNN 唯一的"主超参数"

K 取值模型行为偏差-方差结果
K = 1决策边界由各训练点的 Voronoi 单元拼成，极度曲折偏差极低
方差极高		过拟合的极端形式：训练误差≈0，但一个噪声点能"割出"一整块错误区域，泛化差
中等 K边界被平滑，局部结构仍保留平衡通常最优，由交叉验证决定
K 很大（接近 n）邻居集合覆盖大半数据集，近似一个粗略的全局模型偏差高
方差低		欠拟合。极端 K = n：分类恒为多数类，回归恒为全局均值，完全忽略 x
面试标准答案：K 是控制模型复杂度的"平滑参数"，作用类似核密度估计里的带宽。K 减小 → 模型更复杂、更贴训练数据、更易过拟合；K 增大 → 更平滑、更保守、更易欠拟合。所以 K 必须用交叉验证选。经验起点 K ≈ √n 只是启发式，不是定理。

为什么要取奇数 —— 以及奇数为什么不够

奇数成立的前提非常窄：只有"二分类 + 等权多数投票"时，K = 2m+1 的两类票数之和为奇数、不可能相等，平局才被"参数化地"消除。三种反例：
① 多分类：K=5 时三类票数可能是 2 : 2 : 1，仍是平局
② 加权投票：权重是实数，奇偶毫无作用
③ 距离并列：存在重复样本或浮点误差时，"谁进前 K 个邻居"本身就是平局。

平局处理方案做法优点代价 / 风险
① 取奇数 K二分类下从参数层面消除平局最简单、零成本只对二分类 + 等权投票有效
② 最近邻优先并列类别中选"其中最近的那个邻居"的类别
或扩大 K 直到有人先过半		有几何依据：更近 = 更相似实现略复杂；扩大 K 会引入更远邻居
③ 加权投票（1/d）整数票换成实数权重，几乎总能分出高下常能顺带提升精度（须自己用 CV 确认，见 2.5）权重仍可能完全相等，需兜底
④ 类别先验 / 业务优先级按先验概率或业务优先级打破平局可注入业务知识引入人为偏好，必须文档化
⑤ 确定性兜底按类标签升序取最小 / 固定种子随机保证"同输入同输出"，可测试无种子随机会破坏可复现性，线上禁用
sklearn 的实现细节（易踩）：邻居票数平局时，KNeighborsClassifier.predict 返回"排序/索引最小"的那个类别。这是实现细节，不是接口契约，跨版本可能变化。若平局语义影响业务（风控、医疗分级），应自己实现投票并显式定义平局规则。

如何科学选 K：交叉验证，而不是凭感觉

  1. 候选集合：K ∈ {1, 2, 3, …, 30}，或从小 K 到 ≈√n 的对数间隔
  2. 对每个候选 K 做 k 折交叉验证（5 折或 10 折），取平均指标（分类用 F1；不平衡数据用 macro-F1）
  3. 画"K - CV 分数"曲线：典型形态是先升后降的单峰 / U 形，峰值就是最优区
  4. 平台期可用一倍标准差规则：在"最高分 − 1 个标准差"内选更平滑（更大 K）的那个
  5. 绝对不要用测试集选 K——那是二次数据泄漏，测试分数会虚高

2.4 决策规则

分类：多数投票法

多数投票ŷ = argmaxc ∈ 𝒴 Σi ∈ NK(x) I(yi = c)

其中 𝒴 是类别集合。平局处理见 2.3 的表格。

票数比例形式的概率估计（注意：这不该叫"软投票"——软投票通常指多个模型各自输出概率后取平均）：sklearn 的 predict_proba 返回 K 个邻居中各类别的比例。它常被当置信度用，但必须清楚：这个比例不是校准概率。5 个邻居里 4 票支持某类得到 0.8，并不意味着"80% 的概率是这个类"——它没有考虑邻居本身的标签噪声、类别先验和 K 的选取。需要真实概率要另行校准（Platt scaling、等渗回归）。

回归：平均 / 中位数 / 加权平均

  • 均值：ŷ = (1/K) Σ yi　——最常用，但对邻居中的异常标签敏感
  • 中位数：对标签噪声稳健，代价是输出有偏（不是平方误差意义下的最优）
  • 加权平均：ŷ = Σ wi yi / Σ wi　——见 2.5
小实验：把邻居标签中的一个数值改成极端离群值（房价 500 万里混进一个 5 亿），均值会被显著拖动，中位数几乎不动。选择聚合函数 = 选择对噪声的鲁棒性。

2.5 加权 KNN：让更近的邻居说话更算数

动机：普通 KNN 把第 1 近邻（距离 0.01）和第 K 近邻（距离 1.00）的票权视为完全相等。但 KNN 的全部信念就是"越像越可能是同类"——票权相等直接违背了这个信念。

权重函数公式特点
距离倒数wi = 1 / di（工程上写 1/(di + ε)）最常用；ε 用于数值兜底
距离平方倒数wi = 1 / di²更激进，几乎只信最近的几个邻居；K 很大时行为接近 1-NN
高斯核wi = exp( −di² / (2σ²) )平滑衰减；多了一个要选的带宽 σ
秩权重wi = 1/i 或 (K+1−i)/K只看顺序、不看距离量级（对距离的单调变换免疫）
但换特征缩放会改变"谁是前 K 个邻居"，并不免疫尺度问题
d = 0 的处理（必考点）：查询点与某训练样本完全重合时，倒数权重变成无穷。标准处理：直接返回该样本标签（"精确命中"），或统一使用 wi = 1/(di + ε)，ε 取 10⁻⁸ 量级。

决策规则：分类 ŷ = argmaxc Σ wi I(yi=c)；回归 ŷ = Σ wi yi / Σ wi。

收益：密度不均或类别边界附近通常更准。代价与坑：
① 搜索 K 个邻居的成本完全不变（不是算法加速）
② 对噪声更敏感——若一个错标样本恰好离查询点最近，它的权重最大，错误被放大（缓解：适度增大 K）
③ 数值稳定性（必须处理 d→0）
④ 多了一个超参数。

理论视角（加分项）：加权投票可以看作核平滑（kernel smoothing）/ Parzen 窗思想的离散版本——在查询点周围放一个核函数，邻居按核值加权。当 K → n 且权重由核函数给出时，KNN 回归趋近于 Nadaraya–Watson 核回归。这是 KNN 与核方法之间的一座桥。

03 KNN 完整算法流程 工程实践层 · 专业重点

3.1 完整算法步骤与复杂度

输入：训练集 D = {(xi, yi)}i=1..n、查询样本 xq、邻居数 K、距离函数 d(·,·)、决策规则。输出：预测值 ŷ。

  1. 预处理（离线）：特征清洗、编码、缺失值处理、标准化（参数只从训练集估计）、选择距离度量
  2. 算距离：计算 xq 到每个训练样本的距离 → O(n·d)
  3. 选邻居：取距离最小的 K 个。不需要全排序：用大小为 K 的堆 O(n log K)，或 quickselect 期望 O(n)
  4. 决策：投票 / 加权投票 / （加权）平均 → O(K)
  5. 输出 ŷ
阶段时间复杂度空间复杂度说明
训练（暴力版）O(1)O(n·d)只是把数据存下来
预测（单样本）O(n·d) + O(n log K)O(n) 临时距离数组与训练集大小线性相关
批量预测（m 个）O(m·n·d)—大规模场景的致命项
建索引（KD-Tree，可选）O(n log n) 期望O(n)用训练期开销换预测期速度

3.2 手写伪代码（不调用任何机器学习库）

粒度刻意保持清晰，覆盖"距离计算 → top-K 选择 → 平局处理 → 加权投票"的完整逻辑：

pseudocode完整流程 · 含平局与除零处理
ALGORITHM KNN_PREDICT(D, x_q, K, dist, weights_mode, tie_rule)

  INPUT : D            = 训练集 {(x_i, y_i)}, i = 1..n, x_i 维度为 d
          x_q          = 待预测样本
          K            = 邻居数 (1 <= K <= n)
          dist(a, b)   = 距离函数, 例如 L2 / L1 / cosine
          weights_mode = "uniform" | "distance"
          tie_rule     = "nearest" | "class_prior" | "smallest_label"
  OUTPUT: y_hat (分类标签) 或数值(回归)

  # ---------- 阶段 1：计算距离 ----------
  dists = empty array of size n
  FOR i = 1 TO n:
      dists[i] = dist(x_q, D.x[i])            # 每次 O(d) -> 合计 O(n*d)
  END FOR

  # ---------- 阶段 2：选出距离最小的 K 个（最大堆维护，不全排序） ----------
  heap = empty max-heap keyed by distance      # 堆顶是“当前 K 个里最远的那个”
  FOR i = 1 TO n:
      IF heap.size < K:
          heap.push( (dists[i], i) )
      ELSE IF dists[i] < heap.top().distance:
          heap.pop()                           # 踢掉最远的，换成更近的
          heap.push( (dists[i], i) )
      END IF
  END FOR
  neighbors = sort(heap.items by distance asc)  # 只需对 K 个元素排序 O(K log K)
  # 全程 O(n log K)；若用 quickselect 可做到期望 O(n)

  # ---------- 阶段 3：计算权重 ----------
  FOR each nb IN neighbors:
      IF weights_mode == "uniform":
          nb.w = 1
      ELSE:                                     # 距离加权
          IF nb.distance == 0:                  # 精确命中，直接返回该样本标签
              RETURN D.y[nb.index]
          END IF
          nb.w = 1 / nb.distance                # 工程实现写成 1/(d + 1e-8) 防除零
      END IF
  END FOR

  # ---------- 阶段 4A：分类 -> 加权多数投票 ----------
  IF task == CLASSIFICATION:
      score = {}                                # 类别 -> 累计权重
      FOR each nb IN neighbors:
          score[ D.y[nb.index] ] += nb.w
      END FOR
      best_score = max(score.values)
      winners = { c in score : score[c] == best_score }   # 注意：winners 可能不止一个！

      IF |winners| == 1:
          RETURN the single winner
      ELSE:                                     # ---------- 平局处理 ----------
          SWITCH tie_rule:
              CASE "nearest":                   # 谁有最近的邻居就归谁
                  FOR nb IN neighbors (按距离升序):
                      IF D.y[nb.index] IN winners:
                          RETURN D.y[nb.index]
                  END FOR
              CASE "class_prior":               # 先验概率大的类优先
                  RETURN argmax_{c in winners} prior[c]
              CASE "smallest_label":            # 确定性兜底，保证可复现
                  RETURN min(winners)
          END SWITCH
      END IF
  END IF

  # ---------- 阶段 4B：回归 ----------
  IF task == REGRESSION:
      num = 0 ; den = 0
      FOR each nb IN neighbors:
          num += nb.w * D.y[nb.index]
          den += nb.w
      END FOR
      RETURN num / den                          # uniform 时退化为普通均值
  END IF

END ALGORITHM
三个会被追问的工程细节：
① 堆 vs 全排序：全排序 O(n log n)，堆只要 O(n log K)，n=10⁶、K=10 时差距明显，且堆只需 O(K) 额外内存
② 平局必须显式处理：代码里 winners 是集合，明确写了"可能不止一个元素"
③ 除零保护：1/d 在 d=0 时是 ∞，不处理会得到 NaN 并污染整个投票。

const TRAIN = [
  { x: [1.0, 1.1], y: "A" }, { x: [1.2, 0.9], y: "A" }, { x: [1.6, 1.5], y: "A" },
  { x: [3.1, 2.9], y: "B" }, { x: [3.3, 3.4], y: "B" }, { x: [2.9, 3.2], y: "B" },
];

function euclid(a, b) {                       // L2 距离
  let s = 0;
  for (let j = 0; j < a.length; j++) s += (a[j] - b[j]) ** 2;
  return Math.sqrt(s);
}

function knnPredict(train, query, k) {
  // 1) 算距离并保留标签，距离为 0 时精确命中
  const dists = train.map((p, i) => ({ i, y: p.y, d: euclid(p.x, query) }));
  // 2) 升序排序后取前 k（教学版用排序；工程版用堆或 argpartition）
  dists.sort((a, b) => a.d - b.d);
  const neighbors = dists.slice(0, Math.min(k, dists.length));
  // 3) 多数投票
  const score = {};
  neighbors.forEach(nb => { score[nb.y] = (score[nb.y] || 0) + 1; });
  const best = Math.max(...Object.values(score));
  const winners = Object.keys(score).filter(c => score[c] === best);
  return { neighbors, score, best, winners, tie: winners.length > 1 };
}

3.3.1 Python 手写实现（NumPy 向量化，不调 sklearn）

同一套逻辑（距离 → top-K → 投票）换成工程上真正会写的向量化形式：距离矩阵用一次矩阵乘法算完，top-K 用 argpartition 做部分选择，并显式处理浮点负值、d=0 与平局。

python手写 NumPy 实现 · 不调 sklearn
import numpy as np

def knn_predict(X_train, y_train, X_query, k=5, metric="l2", weights="uniform", task="clf"):
    """
    X_train : (n, d) 训练特征（已标准化）
    y_train : (n,)   训练标签（分类为整数编码 / 回归为浮点）
    X_query : (m, d) 待预测样本（用训练集的缩放参数 transform 得到）
    """
    # ---- 1. 一次广播算出 (m, n) 距离矩阵，避免 Python 层双重循环 ----
    # 利用 ||a-b||^2 = ||a||^2 - 2a·b + ||b||^2，把距离展开成矩阵乘法（走 BLAS）
    if metric == "l2":
        Xq2 = (X_query ** 2).sum(axis=1, keepdims=True)      # (m, 1)
        Xt2 = (X_train ** 2).sum(axis=1, keepdims=True)      # (n, 1)
        D2 = Xq2 + Xt2.T - 2.0 * X_query @ X_train.T         # (m, n)
        D = np.sqrt(np.maximum(D2, 0.0))                     # 裁剪负值：浮点误差会造出 -1e-13
    elif metric == "l1":
        # 曼哈顿距离：(m, 1, d) - (1, n, d) -> (m, n, d)，再用 sum 压缩
        D = np.abs(X_query[:, None, :] - X_train[None, :, :]).sum(axis=2)
    else:
        raise ValueError("unsupported metric: " + metric)

    # ---- 2. 取每行的 top-k 下标；argpartition 只做部分选择，比 argsort 快 ----
    k_eff = min(k, X_train.shape[0])
    idx = np.argpartition(D, kth=k_eff - 1, axis=1)[:, :k_eff]     # 不保证有序，只保证前 k 小
    rows = np.arange(D.shape[0])[:, None]
    d_nb = D[rows, idx]                                            # (m, k) 对应的距离
    order = np.argsort(d_nb, axis=1)                               # 只需对 k 个元素排序
    idx = idx[rows, order]
    y_nb = y_train[idx]                                            # (m, k) 邻居标签
    d_nb = d_nb[rows, order]

    # ---- 3. 权重 ----
    if weights == "uniform":
        w = np.ones_like(d_nb)
    else:
        exact = d_nb == 0.0
        w = 1.0 / (d_nb + 1e-8)                                    # 加 eps 防除零
        if task == "clf" and exact.any():                          # 精确命中：给超大权重近似"直接命中"
            hit_row, hit_pos = np.where(exact)
            w[hit_row, hit_pos] = 1e12

    # ---- 4. 决策 ----
    if task == "clf":
        n_cls = int(y_train.max()) + 1
        onehot = np.zeros((y_nb.shape[0], n_cls))
        np.add.at(onehot, (np.arange(y_nb.shape[0])[:, None], y_nb), w)   # 按权重累加到对应类别
        pred = onehot.argmax(axis=1)
        # 平局检测：最大分数被多个类别并列取得，即发生平局
        tied = (onehot == onehot.max(axis=1, keepdims=True)).sum(axis=1) > 1
        return pred, tied, onehot
    else:
        return (w * y_nb).sum(axis=1) / w.sum(axis=1), None, None
三个容易踩的点：
① ||a-b||^2 的展开式在浮点下可能算出负数，必须 np.maximum(D2, 0.0) 裁剪，否则开方得到 NaN 并静默污染全部结果
② argpartition 只保证前 k 个是最小的 k 个、不保证有序，所以还要对这 k 个再排一次
③ 平局与 d=0 必须显式处理（函数把 tied 作为一等公民返回）。

3.5 工程痛点（本节决定你能否把 KNN 用对地方）

3.5.1 预测复杂度：为什么大数据集上暴力 KNN 不可用

量级估算（n = 10⁶，d = 128）：单次查询乘加次数 ≈ n × d = 1.28 × 10⁸；单精度训练集 ≈ 10⁶ × 128 × 4 B ≈ 512 MB，每个查询都要把它过一遍；按内存带宽 20 GB/s，仅内存读取就要约 25 ms，叠加计算与排序，单次查询轻松到几十毫秒。若要求 QPS = 100、P99 < 50 ms，这套方案在量级上就不成立——不是"优化一下"能解决的。

再叠加两个现实约束：训练集必须常驻内存（O(n·d)，不能像线性模型那样训练完就丢数据）；批量打分放大问题（m 个查询是 O(m·n·d)，离线批任务能接受，在线实时服务不能接受）。

结论：暴力 KNN 的舒适区是中小规模 + 可接受延迟 + 离线批处理。数据一上规模、又要在线低延迟，就必须引入索引结构（精确）或 ANN（近似）。

3.5.2 KD-Tree 与 Ball-Tree：用空间结构换查询时间（准确表述）

先把三句话说准（考试/面试必答）：
① KD-Tree 是对训练集建立的索引结构，建树发生在训练阶段，期望开销 O(n log n)
② 它的作用是降低预测阶段最近邻搜索的开销，不是加速训练——暴力版训练是 O(1)，用了 KD-Tree 反而要在训练期花更多时间，这是"用训练期开销和内存换预测期速度"
③ 它是精确搜索（不是近似），低维下查询期望 O(log n) 量级。

剪枝原理（直觉版）：从根向下搜索时维护"当前找到的最近距离" r。对每个子树，计算查询点到该子树所代表区域的最近可能距离 dbox：若 dbox > r，则该子树里不可能有更近的点，整枝跳过。维度低时空间分割得很开，大量子树能被剪掉；维度高时几乎所有区域的 dbox 都很小，剪不掉，于是退化为遍历全部样本。

为什么高维会退化（必考）：随维度 d 增大，随机样本之间的欧氏距离会集中（最大距离与最小距离之比趋于 1），"最近邻"与"最远邻"的对比度消失，任何基于距离上下界的剪枝都失去判别力 → KD-Tree 退化为 O(n)，与暴力法持平甚至更慢（多了树遍历开销）。实践中可用维度与样本量、数据分布都有关：n 越大、结构越强，可用的维度越高；对相互独立的随机特征，d 到十几时剪枝就明显失效（实验室 5 里可以把这条曲线亲手跑出来）。sklearn 文档的经验是：维度较低（大致 d < 20）时优先考虑 kd_tree，更高维度转向 ball_tree / brute 或直接上 ANN。Ball-Tree 用超球而不是超矩形划分，建树更贵，但在高维与部分非欧度量（曼哈顿、余弦）下更好；sklearn 中 metric='cosine' 只能用 ball_tree 或 brute。

3.5.3 特征尺度：不标准化的真实后果

可以证明的部分（不是实验现象）：若特征 j 的取值范围是特征 k 的 c 倍，则特征 j 对欧氏距离的贡献量级约是 k 的 c 倍；当 c 很大时，距离度量近似退化为"只看特征 j"。推论：其余特征携带的信息被丢弃，模型能力因此下降（例如业务上真正区分两类的是年龄，而距离只反映收入）。

一个常见的错误推论：不能说"预测结果与 K 无关"——c → ∞ 时模型只是退化成一维 KNN，而一维 KNN 的预测仍然依赖 K（K 越大越平滑）。因此判据应当是"标准化前后分数差距明显 + 各特征量级比悬殊"，而不是"K 曲线是否平坦"。

建议自己跑的可复现实验：取任一多特征数据集（如 load_breast_cancer），把某一维人为乘以 1000，比较四种配置的 CV 分数：
① 未标准化 + K=5
② 未标准化 + K 从 1 搜到 30
③ 标准化 + K=5
④ 标准化 + K 从 1 搜到 30。判定标准是 ③、④ 明显优于 ①、②（本机实测：未标准化 best 0.905、标准化 best 0.968），再辅以"各特征 std / 极差的量级比"作为旁证；不要把"标准化前 K 曲线是否平坦"当作判据——退化成一维后的 KNN 仍然依赖 K，曲线不一定会变平。这个实验能让你真的记住尺度问题，也适合直接写进实验报告。

3.5.4 类别不平衡

现象：正类只占 1%，KNN 找出的 K 个邻居大概率全是负类 → 正类召回率接近 0；但 accuracy 依然可以高达 99%，因为全预测负类就是 99%。为什么 KNN 尤其受影响：KNN 的决策完全由局部样本密度决定，而类别不平衡的本质就是密度不平衡——多数类在空间上"包围"少数类。

3.5.5 其他工程坑清单

  • 缺失值：距离对 NaN 零容忍（会传染成 NaN）。先插补；KNNImputer 本身也是 KNN，注意只能在训练集 fit
  • 重复/近似重复样本：K 个"邻居"可能是同一个点，有效 K 变小 → 先去重
  • 无关特征稀释相似度：混入大量无关维度后，做特征选择/降维的收益通常远大于调 K
  • 类别型特征：需编码；one-hot 后欧氏距离含义模糊，考虑汉明/杰卡德或余弦
  • 可复现性：平局策略、随机种子、浮点误差导致的近邻顺序抖动（用稳定排序 + 次键）
  • 训练/推理一致性（线上事故高频来源）：标准化参数、特征顺序、缺失值填充策略、距离度量版本必须与训练时严格一致；建议整条 Pipeline 一起序列化保存
  • 增量更新：KNN 天然支持加样本，但索引结构需重建或增量维护（HNSW 支持插入/删除，KD-Tree 一般需重建）
  • 概率输出：predict_proba 不是校准概率，别用于定价/风控阈值

04 进阶思考：取舍、面试考点与学习延伸 进阶思考层

4.1 KNN 的优点（逐条深度解释）

  1. 无需假设数据分布、无参数化模型：线性模型假设决策边界是超平面，KNN 不做任何全局形式假设，能拟合任意形状的边界（局部、非线性、多峰）。类别边界极不规则、又缺乏领域先验时，这是实质优势。
  2. 天生支持多分类与多输出：从二分类推广到 C 类只是投票表多几列，不需要 One-vs-Rest 之类技巧，也不引入新的超参数。
  3. 训练成本为零、增量友好：新数据到了直接进库就能立刻影响预测（在线学习的雏形），不需要重新训练。适合数据持续增长、模型需要快速吸收新样本的场景。
  4. 可解释性形态独特：给出的是证据样本而不是系数或规则——"这 5 个和你最像的客户都违约了"。在风控、医疗辅助沟通等场景，这比"权重 0.37"更有说服力。
  5. 天然的距离 baseline：任何"相似性"任务的第一版方案都应该是 KNN（或其 ANN 版本）。它给出下限参考：深度模型打不过 KNN，说明特征或训练流程有问题。
  6. 实现简单、可嵌入：几十行代码就能实现，可以塞进不支持机器学习的运行环境（嵌入式、数据库 UDF，甚至 SQL）。

4.2 KNN 的缺点（逐条深度分析）

  1. 预测复杂度 O(n·d)：最致命的缺点。KNN 把成本从训练搬到推理，而在线系统对推理成本最敏感。规模一大就必须用索引或 ANN。
  2. 空间复杂度 O(n·d) 常驻：模型即数据、无法压缩。对比 SVM 只存支持向量、线性模型只存参数——这是"知识是否被压缩"的本质差别。
  3. 维度灾难：高维下所有点距离趋于相近，最近邻不再显著比最远邻更近，"局部平滑假设"崩塌；同时 KD-Tree 剪枝失效、维持相同密度所需样本量随维度指数增长。→ 应对：降维（PCA）、特征选择、度量学习。
  4. 对特征尺度与无关特征极度敏感：距离对所有维度等权求和，未标准化的量纲或大量无关特征会直接污染"相似度"的定义。这就是"特征工程决定 KNN 成败"的原因。
  5. 类别不平衡下系统性偏向多数类：因为它是密度驱动的模型，见 3.5.4。
  6. 要求"距离有意义"：混合类型特征（连续 + 类别 + 文本）上欧氏距离没有语义；度量选错，调 K 也救不回来。
  7. 无法外推（回归）：输出必然是邻居标签的（加权）平均，永远落在训练标签值域内。趋势、周期、外推任务必须换模型。
  8. 标签噪声直接进决策：没有"参数平滑"这一层，一个错标样本会在其邻域持续制造错误预测（K 小时尤甚）。
  9. 不可微、无法梯度优化：不能端到端训练，也难以与神经网络联合优化。现代做法是"用神经网络学 embedding，再在 embedding 空间做 KNN/ANN 检索"——KNN 没被淘汰，而是被搬进了表示空间。
  10. 概率输出未校准：predict_proba 只是邻居票数比例，不能当真实概率用。
  11. 数据治理成本高：数据即模型，删除隐私数据（合规要求）、修正错标、版本回滚都要直接操作"模型本体"，比重新训练一个参数文件麻烦得多。

4.4 面试考点（点击展开参考回答）

惰性学习是什么？KNN 为什么算惰性学习？它是不是"不需要训练数据"？

要点：惰性学习指没有显式的训练/参数估计过程，计算被延迟到预测阶段。KNN 训练阶段只是存储数据（O(1)），预测阶段才做距离计算、排序、投票。它必须有训练数据——数据就是模型，没有数据就没有任何预测能力。

追问：KNN 的训练复杂度？→ 暴力版 O(1)；用 KD-Tree 时建树 O(n log n)，属于训练期开销，"训练"不再是零成本。

常见错误：说"KNN 不需要训练数据"，或把 KD-Tree 建树说成"加速训练"。

K 为什么一般取奇数？奇数一定能避免平局吗？平局有哪几种处理方式？

要点：奇数只在二分类 + 等权多数投票下保证无平局（票数之和为奇数）。多分类、加权投票、距离并列时仍可能平局。处理方式：奇数 K、最近邻优先、距离加权投票、类别先验/业务优先级、确定性兜底（最小类标签 / 固定种子）。

加分：指出 sklearn 平局时返回索引最小的类别，属实现细节而非接口契约；需要严格受控时自行实现投票。

K 不能取 1 吗？K=1 的问题是什么？

要点：不是"不能"，而是"不稳健"。K=1 时训练误差≈0（每个训练点离自己最近），但方差极大、对噪声与离群点极度敏感，决策边界是 Voronoi 拼图，容易过拟合。噪声低、类别可分时 K=1 也能用；工程上默认从较大 K 起搜，由交叉验证决定。

追问：K 增大会怎样？→ 边界变平滑、偏差上升方差下降；K=n 退化为多数类（分类）/全局均值（回归），完全欠拟合。

为什么要归一化/标准化？min-max 与 Z-score 的区别？标准化有什么风险？

要点：距离对所有维度等权累加，量级大的维度会支配距离（数学必然）。min-max 映射到固定区间 [0,1]，依赖 min/max、对离群值敏感；Z-score 使均值 0 方差 1，无界、相对稳健，是距离类算法的默认选择。

风险/不宜场景：稀疏文本 + 余弦（破坏稀疏性）、树模型（无收益）、缩放参数在全量数据上估计会造成数据泄漏（必须放进 Pipeline）。

加分：提到稳健缩放（中位数 + IQR）。

KD-Tree 的加速原理？为什么高维会退化？它加速训练还是预测？

要点：对训练集递归按维度切分（中位数），形成超矩形区域的二叉树；查询时用"查询点到子区域的距离下界 > 当前最近距离"整枝剪枝。加速的是预测（近邻搜索），建树是训练期额外开销 O(n log n)。高维时距离集中、剪枝条件失效 → 退化为 O(n)。经验上维度超过约 20～30 收益基本消失，此时改用 Ball-Tree 或 ANN。

KNN 的时间/空间复杂度？怎么优化到能上线？

要点：训练 O(1)（暴力）；预测 O(n·d) 计算 + O(n log K) 选邻居；空间 O(n·d)。

优化路线：
① 向量化实现（去掉 Python 循环，用 BLAS）
② 部分选择代替全排序（堆 / argpartition）
③ 精确索引（KD-Tree / Ball-Tree，低维有效）
④ 近似最近邻（HNSW / IVF-PQ），允许少量精度损失换数量级加速
⑤ 降维 / 量化减少 d 与内存
⑥ 离线预计算候选 + 线上重排
⑦ 缓存热门查询
⑧ 分批 / GPU 检索。

KNN 为什么在不平衡数据上表现差？除了重采样还能做什么？

要点：KNN 决策依赖局部密度，不平衡 = 密度不平衡，多数类在空间上包围少数类。除重采样外：换指标（macro-F1/PR-AUC/逐类 recall）、距离加权投票、调小 K、自定义类别权重投票（注意 sklearn 的 KNN 没有 class_weight）、代价敏感学习、换模型。

写代码题：手写 KNN，要求效率高且平局行为确定

要点：不要用双重循环；用广播/矩阵乘法算距离矩阵；用 argpartition 取 top-K 而不是 argsort；对 K 个邻居排序后加权投票；显式处理平局与 d=0；注意 ||a−b||² 展开式可能产生负值需 clip。面试官往往就是看你有没有考虑这些细节。

KNN 回归为什么不能外推？加权 KNN 的权重怎么设计？d=0 怎么办？

外推：输出是邻居标签的加权平均，数学上落在邻居标签最小值与最大值之间，不可能超出训练标签值域，也无法表达趋势/周期。

权重：1/d、1/d²、高斯核 exp(−d²/2σ²)、秩权重 1/i。d=0 时精确命中直接返回该样本标签，或统用 1/(d+ε)。权衡：更强的局部性 vs 对近处噪声更敏感；且不影响搜索成本。

高维空间中精确最近邻没有亚线性的一般算法（维度灾难）。工程上于是做精度-速度-内存的三角权衡，允许少量召回损失换取数量级加速：

HNSW 参数直觉：M = 每节点邻居数（越大越准越占内存）；efConstruction = 建图搜索宽度（越大图质量越好、建图越慢）；efSearch = 查询搜索宽度（越大越准越慢）——这是能在运行时调节"精度 ↔ 延迟"的旋钮之一（IVF 的 n_probe 同理，也是运行时旋钮），工程上非常实用。

向量数据库与 RAG：KNN 的现代形态

把"embedding 向量 + ANN 索引 + 元数据过滤"打包成服务，就是向量数据库：Milvus、Qdrant、pgvector、FAISS（库）、Chroma 等。它们的核心操作仍然是最经典的 KNN：给定查询向量，按距离度量找 Top-K 相似向量。所以：

  • 检索语义：距离度量 + Top-K + "相似即相关" —— 与 1950 年代的 KNN 判断完全一致
  • RAG（检索增强生成）：文档切块 → embedding → 存向量库 → 查询时用 ANN 取回 Top-K 片段 → 交给大模型生成答案。KNN 是 RAG 的检索内核
  • 关注点从"算法"变成"系统"：召回率@K、延迟、索引内存、批量重建、过滤条件与向量检索的联合优化

度量学习：把"怎么算距离"变成学出来的

KNN 最大的软肋是"距离由人设计"。度量学习反过来：用数据学习一个映射 f，使得在 f(x) 空间里"同标签距离近、异标签距离远"（对比学习、三元组损失）。于是现代范式变成：神经网络学表示 + 距离度量在 embedding 空间生效 + ANN 做检索。这不是抛弃 KNN，而是把 KNN 从原始特征空间搬到了学出来的表示空间——KNN 的思想在深度学习时代反而更重要了。

5.1 分层小结

入门层（第1章）

  • 唯一假设：相似的输入有相似的输出；KNN 是"现场问邻居"，不是"先学一个公式"
  • 惰性学习：有训练数据、没有训练过程，计算全部推迟到预测阶段
  • 三要素：距离度量、K 值、决策规则

原理层（第2章）

  • 距离定义了"相似"：L1 稳健、L2 默认、余弦看方向、马氏去相关
  • 量纲不一致会让距离退化到"只看量级最大的那一维"；归一化（有界）≠ 标准化（无界）
  • K 是复杂度旋钮：小 K 过拟合、大 K 欠拟合，必须交叉验证选
  • 奇数 K 只在"二分类 + 等权投票"下消除平局；平局处理必须显式定义
  • 加权 KNN：用 1/d 放大近邻话语权，代价是更怕近处噪声

工程层（第3章）

  • 流程：标准化 → 算距离 → 部分选择 top-K → 投票/平均；预测 O(nd)、空间 O(nd)
  • 优化：向量化（BLAS）、argpartition/堆、KD-Tree/Ball-Tree（加速预测，不是训练）、ANN
  • 高维下 KD-Tree 剪枝失效退化为 O(n)；维度灾难是根本限制
  • 不平衡数据偏向多数类；KNeighborsClassifier 没有 class_weight
  • 数据泄漏红线：缩放器只能 fit 训练集，且必须放进 Pipeline

进阶层（第4章）

  • 价值：普适的"相似性"视角；限制：知识不压缩 + 推理昂贵
  • 选型标准见 4.3；现代延续：embedding + ANN（HNSW / IVF-PQ）+ 向量数据库 + RAG + 度量学习

5.2 课后思考题（5 题，点击展开参考解答）

Q1（工程分析）实时推荐场景的技术选型

某电商要用 KNN 思想做"实时猜你喜欢"：1 亿条商品向量，每条 128 维，要求 P99 延迟 < 50 ms、QPS = 2000。
① 直接用 sklearn.neighbors.KNeighborsClassifier（暴力搜索）是否可行？请用数量级估算说明（计算量 + 内存）。
② 给出至少三条改造方案，并分别说明代价。
③ 若业务允许 3% 召回损失，你会怎么改？若不允许任何召回损失呢？

参考解答要点
① 不可行。计算量：单次查询 n×d = 10⁸ × 128 ≈ 1.28 × 10¹⁰ 次乘加；内存：10⁸ × 128 × 4 B ≈ 51.2 GB（float32），单机难以常驻，且每次查询都要全量扫描。即便多核并行，2000 × 1.28 × 10¹⁰ 也远超单机算力，量级上不成立。
② 方案：ANN 索引（HNSW：召回高延迟低，代价是索引内存大、建图慢、需调 M/efSearch）；IVF-PQ（聚类 + 乘积量化：内存压缩几十倍、速度极快，代价是量化误差导致召回损失）；降维（PCA/自编码器降到 32～64 维，代价是损失部分可分性）；两阶段（离线预计算候选 + 线上轻量重排，代价是新鲜度/一致性管理复杂）；GPU 检索（FAISS-GPU，代价是硬件成本与批处理调度）。
③ 允许 3% 损失 → 上 ANN，把 efSearch / n_probe 调到刚好满足召回指标的最小值，并监控线上召回率与点击率。不允许任何损失 → 精确性只能保留在小候选集上：用 ANN 做召回（可取数千候选），再对小集合做精确重排（两阶段），这是工业界常用折中；纯精确在这规模上不现实。
Q2（原理辨析）"KNN 不需要训练数据，是最简单的机器学习算法"

请指出这句话的两处错误，并从惰性学习、复杂度分布、模型容量三个角度说明为什么"简单"这个评价有误导性。

参考解答要点
错误一："不需要训练数据"——KNN 必须有训练数据，数据就是模型；它只是不需要显式的训练过程。
错误二："最简单"——概念简单，但工程复杂度不低：预测 O(nd)、内存 O(nd)，还要处理尺度、K 选择、平局、不平衡、维度灾难、索引结构、数据泄漏等一整套问题。
三个角度：
① 惰性学习 → 训练成本被搬到推理，线上延迟成为瓶颈
② 复杂度分布 → 训练 O(1) / 推理 O(nd)，与"训练贵、推理便宜"的常规直觉相反，部署形态完全不同
③ 模型容量 → 容量随 n 增长（非参数化），不能压缩存储，泛化依赖数据密度，高维下需要指数级样本量。结论：KNN 是"定义简单、工程不简单"的算法。
Q3（实验设计）如何证明"问题出在尺度上"

你在数据集 A 上得到 macro-F1 = 0.92，在数据集 B 上只有 0.71，怀疑是特征尺度问题。请设计实验方案验证（要求：对比基线、控制变量、评估方式，并说明如何排除数据泄漏）。

参考解答要点
对比组：固定模型与数据划分（同一 random_state、同一 stratify、同一 CV 折），只改预处理：
① 原始 + L2
② Z-score + L2
③ min-max + L2
④ 稳健缩放（中位数 + IQR）+ L2
⑤ 若含离群值再对比 L1。
控制变量：模型、K 搜索区间、CV 折数、评估指标保持一致；scaler 必须放进 Pipeline，否则 CV 分数虚高、结论不可信。
诊断证据（关键）：不只看分数，看四件事：
① 标准化前后分数差距（主证据，本机实测 0.905 → 0.968）
② 各特征量级（std / 极差比值）
③ 逐类 recall（排除不平衡干扰）
④ 只保留量级最大那一维做消融。"K-分数曲线"只能当旁证：不要把"标准化后曲线一定变单峰"当必要条件——尺度问题与曲线形状没有必然联系。若标准化前后分数基本不变，问题在别处。
排除其他原因：类别不平衡（已用 macro-F1，并检查逐类 recall）；维度/特征数（消融：只保留量级最大的那一维，若性能与全特征接近，正是"距离被单维支配"的证据）；噪声/错标（查重复样本与离群点）；分布漂移（若是漂移而非尺度，标准化救不了）。
结论标准：只有"标准化前后差异显著 + K 曲线形态从异常变正常"同时成立，才能下"是尺度问题"的结论。
Q4（原理辨析）K 与两条误差曲线

K 从 1 增大到 n，训练误差与测试误差分别如何变化？为什么 K=1 时训练误差接近 0？K=n 时会发生什么？

参考解答要点
K=1 时训练误差≈0：每个训练样本与自己的距离为 0，必然把自己选为最近邻，只要没有重复样本且标签唯一，训练集上预测永远正确。这不能说明模型好，恰是过拟合的信号。
训练误差随 K 增大而上升（总体趋势，非严格单调；邻居里混入越多样本，局部拟合能力下降）；K=n 时分类退化为"恒预测多数类"，训练误差 = 1 − 多数类占比（回归退化为恒定全局均值）。
测试误差呈 U 形（先降后升）：K 很小时方差大（对噪声敏感），K 很大时偏差大（过于平滑）。最优点在谷底附近，且随样本量增大而移动（数据越密，最优 K 通常越大）。
结论：训练误差不能作为选 K 的依据（K=1 训练误差最小但泛化最差），必须用验证集/交叉验证。
Q5（工程取舍）让预测"确定性"可复现

线上服务发现同一用户、同一特征输入，两次调用返回的类别偶尔不同。请列举所有可能原因，并给出让系统确定性的方案。

参考解答要点
可能原因：
① 平局处理依赖未固定顺序/随机（或依赖会变化的类别索引顺序）
② 浮点误差 + 并行归约顺序不同 → 距离排序在极接近处抖动
③ 训练集发生变化（增量入库、删样本）但模型版本没变
④ 使用近似检索（HNSW/IVF），参数或索引状态变化
⑤ 预处理版本不一致（scaler 参数、特征顺序、缺失值填充策略变更）
⑥ 缓存命中/未命中走了不同代码路径
⑦ 多线程/GPU 归约不确定。
确定性方案：显式定义并固定平局规则（确定性规则，禁止无种子随机）；对"距离相等"的邻居用稳定排序 + 次键（样本 ID）打破；把预处理 + 模型 + 平局策略打包成版本化产物（保存整个 Pipeline）并固定版本；精确检索或固定 ANN 索引快照（含随机种子与索引参数）；上线前做"同输入重复调用 1000 次结果完全一致"的回归测试；记录每次预测的模型版本/索引版本/预处理版本以便审计。
